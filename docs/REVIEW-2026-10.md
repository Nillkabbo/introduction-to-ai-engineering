# Technical Review and Update Plan (October 2026)

This document records a chapter-by-chapter technical review of *Introduction to AI Engineering*, which was last updated in July 2025. It compares the book against the state of the field as of **18 October 2026**, lists what is wrong or outdated, and describes the corrections made on this branch.

## How the review was done

- Every chapter was read in full, and every code example was checked for correctness: does it run, does it do what the prose claims, and does the claim hold up?
- Facts that changed after July 2025 were checked against current sources rather than memory:
  - Model IDs, method names and response shapes were taken from the current SDK packages on PyPI (`openai` 3.35, `anthropic` 1.15, `google-genai` 2.31, `langchain` 1.4, `mcp` 2.3, `chromadb` 1.5).
  - Platform status (API deprecations, the fine-tuning platform) was checked against vendor documentation and release notes.
- The guiding principle was **correct, current and minimal**: fix what is broken or misleading, add what a practitioner can't do without in 2026, and leave alone what is merely a matter of taste. No chapters were added or removed.

## What changed in the field since July 2025 (and why it matters for this book)

| Area | July 2025 (book) | October 2026 (now) | Impact |
|---|---|---|---|
| OpenAI API | Chat Completions, `gpt-4o-mini` / `gpt-4o` | **Responses API** recommended for new work; Chat Completions still supported. The Assistants API was shut down on 26 Aug 2026. The current family is GPT-6 (`gpt-6-luna`, `gpt-6-sol`, `gpt-6.1-sol`, `gpt-6-astra`), and GPT-4-series removal was announced for Jan 2027. | Every OpenAI example needs a model update. The core OpenAI chapters should teach the Responses API. |
| Reasoning models | Mentioned implicitly | Current flagship models reason by default. `temperature`/`top_p` are rejected unless reasoning is turned off (`reasoning={"effort": "none"}`, on models that allow it). | Examples that set `temperature=0` fail on current models. "Let's think step by step" is mostly redundant on them. |
| Anthropic API | `claude-3-5-sonnet-20240620` | That model is retired. Current models are `claude-opus-5-5`, `claude-sonnet-5-5` and `claude-haiku-5-5`; thinking is on by default; native structured outputs; forced `tool_choice` is rejected on the newest models. | `message.content[0].text` breaks because the first block can be a `thinking` block. |
| Google API | `google-generativeai` SDK, `gemini-1.5-*` | The old SDK is deprecated and replaced by **`google-genai`** (`genai.Client()`). The Gemini 1.5 models are retired; current models include `gemini-3.6-flash`, `gemini-3.8-flash` and `gemini-4-argon`. The Interactions API is the new default interface, while `generate_content` remains fully supported. | Chapter 7 and every Gemini snippet must be migrated. |
| Tool standards | — | **Model Context Protocol (MCP)** is the de facto standard for exposing tools and data to models. | Missing from the book entirely. |
| Structured output | JSON mode + manual Pydantic validation | Schema-enforced **Structured Outputs** on all three providers (`responses.parse`, `messages.parse`, `response_schema`). | Chapter 11 teaches the weaker technique as the "gold standard". |
| Cost levers | Model routing, prompt trimming | **Prompt caching** (cached input billed at a fraction of normal input) and **Batch APIs** (~50% off) are the biggest levers. | Missing from Chapter 21. |
| Security | Direct prompt injection | **Indirect prompt injection** (through documents, web pages and tool results) is the main threat to agents and RAG. OWASP Top 10 for LLM Apps 2025; the "lethal trifecta". | Missing from Chapter 22. |
| Frameworks | LangChain `AgentExecutor`, AutoGen | LangChain 1.x `create_agent` (`AgentExecutor` moved to `langchain-classic`). AutoGen is in maintenance mode, succeeded by Microsoft Agent Framework. The OpenAI Agents SDK, Claude Agent SDK and Google ADK now exist. | Chapter 15's framework code is outdated. |
| Fine-tuning | OpenAI fine-tuning of `gpt-3.5-turbo` | OpenAI's fine-tuning platform has been closed to new users since 8 May 2026. Open-weight fine-tuning (LoRA/QLoRA) and cloud-platform tuning are the main routes. | Chapter 26 needs a status note and an honest framing. |
| Tokenizers | `tiktoken.encoding_for_model("gpt-4o-mini")` | `tiktoken` cannot map the newest model names. Providers expose exact server-side token counting. | Chapter 2's code fails on current model names. |

## Cross-cutting conventions applied on this branch

1. **One default model per provider, defined once per chapter** (for example `MODEL = "gpt-6-luna"`), with a note that model IDs change and should live in configuration. More capable tiers are `gpt-6-sol`, `claude-opus-5-5` and `gemini-4-argon`.
2. **OpenAI examples use the Responses API** (`client.responses.create(...)`, `response.output_text`). Chapter 5 shows the Chat Completions equivalent so readers can work with existing code.
3. **No `temperature` on reasoning models.** Determinism comes from structured outputs and constrained label sets, not `temperature=0`. Chapter 5 explains when sampling parameters apply.
4. **Claude text is read by block type** (`next(b.text for b in msg.content if b.type == "text")`), never `content[0]`.
5. **Gemini uses `google-genai`** (`client.models.generate_content`, `client.files.upload`, `client.chats.create`).
6. **Tool loops handle every tool call in a turn** and keep looping until the model stops calling tools.
7. **Async web endpoints use async clients** (`AsyncOpenAI`), so a slow model call does not block the event loop.
8. **Placeholder or simulated code is labelled as such**, and hard-coded "AI output" is never presented as real output.

## Findings by chapter

Severity labels: **Bug** means the code fails or contradicts the prose. **Wrong** means a factual or technical claim is incorrect. **Outdated** means it was true in July 2025 but not now. **Gap** means important missing content.

### Introduction, Chapter 1 (Welcome)
- Outdated: all model names. The model landscape section lists `claude-3-5-sonnet` (retired) and `gpt-4o`.
- Wrong: the "under the hood" section says the model predicts a sequence of vectors that is decoded back into text. LLMs generate one token at a time from a probability distribution (autoregressive decoding).
- Wrong: the tokenization example splits `" "` and `"world"` into separate tokens. BPE tokenizers attach the space (`" world"`), which also contradicts Chapter 2.
- Gap: the Responses API and the idea that model IDs belong in configuration.

### Chapter 2 (Tokens, embeddings, context)
- Bug: `tiktoken.encoding_for_model(...)` fails for current model names. The printed token IDs are not the IDs `gpt-4o-mini` produces (they look like GPT-2 vocabulary IDs).
- Wrong: "five to six times more expensive". The two example prompts differ by roughly 3x.
- Wrong: "If a conversation exceeds the context window, the model starts to forget". In fact the API rejects the request (or your code must truncate); the model does not silently forget.
- Outdated: the context-window table (`gpt-4-turbo`, `claude-3-5-sonnet`, `gemini-1.5-pro`).
- Bug: `manage_conversation_history` mutates the caller's list, can loop until it raises `IndexError`, and leaves no room for the output.
- Gap: exact token counting with the provider APIs; "lost in the middle" / long-context degradation.

### Chapter 3 (Environment)
- Outdated: "Python 3.9 or higher". Python 3.9 is end-of-life, and current SDKs (Anthropic SDK 1.x, LangChain 1.x) require 3.10+.
- Gap: PowerShell activation command; `uv` as a modern alternative.
- Bug: when an API call fails, the user message stays in history with no reply, which corrupts later turns.

### Chapter 4 (Capabilities and limitations)
- Outdated: "LLMs cannot access the internet". Many APIs now offer built-in web search tools; the right framing is "only if you give them a tool".
- Wrong framing: reasoning models do 3-digit multiplication reliably. The lesson (use code for exact computation) still holds but needs a better justification.
- Wrong: self-reported confidence scores are presented as a "strong signal". Verbalized confidence is poorly calibrated.
- Gap: a safer alternative to `eval()` (a restricted arithmetic evaluator, or tool calling).

### Chapter 5 (OpenAI)
- Outdated: teaches only Chat Completions with `gpt-4o-mini`/`gpt-4o`, `max_tokens`, `tts-1`, and the deprecated `response.stream_to_file`.
- Bug: the function-calling example handles only the first tool call.
- Gap: the Responses API, reasoning effort, and when `temperature` applies.

### Chapter 6 (Claude)
- Bug: the first example hard-codes `api_key="YOUR_ANTHROPIC_API_KEY"` despite its comment saying an environment variable is used.
- Outdated: the retired `claude-3-5-sonnet-20240620` is used throughout.
- Bug: `message.content[0].text` breaks when thinking is enabled (the default on current models).
- Bug: the tool example ignores parallel `tool_use` blocks.
- Outdated or opinion: the provider comparison table claims Claude has a "superior" 200K context, but all three providers now offer 1M-token contexts. It was replaced with selection criteria.
- Gap: PDF input, prompt caching, structured outputs.

### Chapter 7 (Gemini)
- Outdated: the entire chapter uses the deprecated `google-generativeai` SDK and the retired `gemini-1.5-*` models.
- Bug: the PDF upload never checks for a `FAILED` state.

### Chapter 8 (API patterns)
- Bug: `naive_ai_call` contains a `try` block with only a comment in it, which is a SyntaxError.
- Bug: the multi-provider client returns hard-coded stub strings, so the failover demo cannot fail over. Gemini was also configured after the client was created.
- Gap: the official SDKs already retry twice by default, so stacking `tenacity` on top multiplies retries. The retry list was missing connection errors and 5xx errors.
- Wrong: the cache key ignores generation parameters, and caching sampled (non-deterministic) answers is not discussed.
- Wording: "batch response" was confused with the provider Batch APIs.

### Chapter 9 (Prompt fundamentals)
- Bug: `datetime` and `json` are not imported in the final project.
- Outdated: "Let's think step by step" is presented without the reasoning-model caveat.
- Wrong: the claim that personas reliably improve accuracy (the evidence is mixed: personas shape tone and focus more than correctness).
- Wrong: the "A/B testing" example runs a single input with no scoring. It was replaced with a small labelled evaluation.
- Gap: delimiters and XML tags for untrusted input.

### Chapter 10 (Advanced prompting)
- Bug: self-consistency votes on free-text answers, so `Counter` almost never finds agreement. It was changed to vote on a constrained label.
- Bug: the ReAct loop crashes if the output lacks `Action:`, has no finish action, and its termination check can never succeed with the demo tools.
- Bug: Reflexion's keyword heuristic ("missing", "incomplete") nearly always triggers. History leaks between calls. Without an external signal, self-reflection is weak (see Huang et al., 2023).
- Gap: the "Prompt Chaining" section is promised in the objectives and README but missing.
- Reference: a Veo 3 video-prompting article was irrelevant. It was replaced with the original papers.

### Chapter 11 (Structured output)
- Gap/Outdated: native Structured Outputs (schema-enforced decoding) is missing, while JSON mode plus Pydantic is called the gold standard.
- Bug: a nested triple-backtick fence inside a Python string breaks the Markdown rendering.
- Wrong: using an LLM to fill a template with fixed parameters. Deterministic templating (`str.format`/Jinja2) is correct; the LLM should only write the logic.
- Bug: the return type says `DeviceAnalysis` but the function returns `None` on failure.

### Chapter 12 (Domain prompting)
- Bug: `"As {persona}"` renders as "As You are a…", and the pattern lists render as "- - item".
- Wrong: the LLM is asked to "calculate" OEE, contradicting Chapter 4. OEE is now computed in code (the correct value for the sample data is **84.4%**: Availability 90% × Performance 98.8% × Quality 95%).
- Wrong: the prompt asks whether the process is "in statistical control" based on a single shift summary, which invites hallucination.

### Chapter 13 (Agents)
- Bug: `MemorySystem.recall()` raises `TypeError` because the stored `datetime` is not JSON-serializable.
- Bug: the reasoning engine never tells the LLM which actions exist, so the LLM invents action names.
- Bug: synchronous LLM calls inside `async` code block the event loop. The timing comment (3 cycles / 30 s) contradicts the code.
- Gap: workflows vs. agents; human approval for consequential actions.

### Chapter 14 (Tools)
- Bug: the second API call omits `tools=`, so the model cannot call `restart_device`. The "final response" is a hard-coded string. This was replaced with a real loop.
- Outdated: the Claude snippet uses a retired model and omits the required `max_tokens`. The Gemini snippet uses the old SDK.
- Wrong: the "secure" sandbox claims static analysis (none is implemented) and process isolation. The subprocess actually inherits environment variables (API keys), the filesystem and the network.
- Gap: MCP, strict schemas, and tool results as a prompt-injection channel.

### Chapter 15 (Production agents)
- Outdated: `create_openai_tools_agent`, `AgentExecutor` and `ConversationBufferMemory` (LangChain 1.x uses `create_agent`). AutoGen is in maintenance mode.
- Bug: `ProductionAgent` calls a synchronous `load()` on a store whose interface is `async`.
- Wrong: the Redis store uses `pickle`, a deserialization risk; it now uses JSON.
- Gap: newer agent SDKs, step and cost limits, idempotent tools, durable execution.

### Chapter 16 (Multi-agent)
- Wrong: the voting demo says Finance's rejection may cause a tie or rejection, but the code yields a 2–1 PASS.
- Gap: when *not* to use multiple agents (token cost, context fragmentation); orchestrator–worker as the proven pattern.
- Bug: the fallback `self.agents[0]` crashes when no agents are registered.

### Chapter 17 (Web apps)
- Bug: `async def` endpoints call the synchronous OpenAI client, which blocks the event loop. Streaming iterates a synchronous stream inside an async generator.
- Bug: the image endpoint reads the whole file before validating it, and hard-codes `image/jpeg` in the data URL.
- Wrong: it refers to "the chapter's source code", which does not exist in the repository. `PyPDF2` is deprecated in favour of `pypdf`; current models also accept PDFs directly.

### Chapter 18 (Real-time)
- Bug: `broadcast` crashes if a client has disconnected.
- Wrong: the L1 cache never expires, so it serves stale data; it is unbounded.
- Wrong: the claim that Celery workers would pull from a custom Redis ZSET (Celery has its own priority support).
- Gap: LLM latency means LLMs should stay off sub-second control loops.

### Chapter 19 (Architecture)
- Bug: the config loader cannot validate its own example YAML (top-level keys don't match the schema), and `ModelConfig` has no model-name field.
- Wrong: the "AI service on GPU instances" claim, which does not apply when calling hosted APIs.
- Gap: Postgres + pgvector as a pragmatic default before polyglot persistence; an LLM gateway.

### Chapter 20 (Scaling)
- Bug: `Optional` is not imported, and an unused `BackgroundTasks` is imported.
- Wrong: sticky sessions recommended "to keep context in a local cache", which contradicts the chapter's own advice to externalize state.
- Gap: for API-based apps the first bottleneck is the provider's rate limits (TPM/RPM), not your servers. Data residency when replicating across regions.

### Chapter 21 (Cost)
- Outdated: the price table (`gpt-4o` at $5/$15 was already stale; the listed models are retired).
- Wrong: the `tiktoken`-based estimate for non-OpenAI models. Use the `usage` fields returned by the API.
- Gap: prompt caching and Batch APIs, the two largest levers.
- Wrong: "prompt batching" claims "per-request overhead" savings and "better token compression"; replacing newlines with `|` "to save tokens" is a negligible micro-optimization that can hurt quality.
- Wrong: the TF-IDF semantic cache. The threshold claim does not hold, and similar-looking queries for *different* entities (T-101 vs. T-102) produce dangerous false hits.

### Chapter 22 (Security)
- Gap: indirect prompt injection, OWASP LLM Top 10, least-privilege tools, the lethal trifecta.
- Wrong: the regex deny-list (for example `act as`) is presented as a defence. It blocks legitimate input and is trivially bypassed.
- Bug: the intent classifier compares free text with `==`. `Field` is not imported. `datetime.utcnow` is deprecated. The `(str, dict)` return annotation is invalid.
- Wrong: the healthcare example sends the patient ID to the LLM and then claims no sensitive data is ever exposed. Regex anonymization is not HIPAA de-identification. The `is_alert` keyword heuristic is nearly always true.

### Chapter 23 (Observability)
- Bug: the traffic simulator adds work to a fresh `BackgroundTasks()` that nothing ever runs. `log.info("...", ...)` passes a literal Ellipsis. The metrics port conflicts with uvicorn's port.
- Outdated: `@app.on_event("startup")` (use lifespan).
- Gap: OpenTelemetry GenAI semantic conventions, LLM-specific tracing tools, how to actually measure quality, and the PII risk of logging full prompts.

### Chapter 24 (Testing)
- Bug: the integration, regression and validator tests patch `Completions.create` on the class but inject a separate `MagicMock()` client, so the assertions fail.
- Bug: `openai.OpenAI()` at import time requires an API key in CI.
- Wrong: the "regression test" mocks the judge it is supposed to test. It uses an LLM judge to compare `"UNSAFE"` with `"UNSAFE"`, where exact-match accuracy is correct. There is an `assert True` placeholder test.
- Gap: LLM-judge calibration and bias, eval tooling, and why authorization must not be delegated to an LLM.

### Chapter 25 (DevOps)
- Bug: the `name's:` typo makes the workflow YAML invalid; `pytest --mock` is not a pytest flag; the action versions are outdated.
- Bug: feature-flag bucketing uses Python's `hash()`, which is randomized per process, so users flip between variants.
- Wrong: an LLM "decides" a fleet-wide firmware rollout. Canary gates must be metric thresholds; the LLM can summarize.
- Gap: model deprecations and pinning snapshot IDs, treating model upgrades as deployments.

### Chapter 26 (Fine-tuning)
- Outdated: `gpt-3.5-turbo` fine-tuning; the job ID prefix; OpenAI's platform is closed to new users.
- Wrong: the project fine-tunes a model to memorize error codes, which the chapter itself says is the wrong use. It has 4 examples and hard-coded "after" output. It also uses the same fictional product name as Chapter 27 with contradictory error codes.
- Gap: open-weight fine-tuning (LoRA/QLoRA), distillation, and evaluating against a strong prompted baseline.

### Chapter 27 (RAG)
- Wrong: "the AI will politely inform you it has no information". The real risk is a confident fabrication.
- Bug: `langchain-text-splitters` is not installed by the shown command. The Chroma collection handling depends on a return type that changed across versions. Re-adding a file collides on IDs.
- Gap: hybrid search, reranking, metadata, relevance thresholds, RAG evaluation, long-context vs. RAG, and injection through documents.

### Chapter 28 (Workflows)
- Bug: the orchestrator passes inputs as keyword arguments named after dependency IDs, but the task functions use different parameter names, so **every task fails with `TypeError`**. `json` and `time` are not imported.
- Gap: durable execution for human-in-the-loop steps that wait hours or days; cycles in agent graphs.

### Chapter 29 (Trends)
- Outdated: "true multimodality" is presented as next-generation (it is now mainstream). It misses the trends that defined 2025–26: reasoning models, coding/computer-use agents, MCP/A2A, open-weight and on-device models.
- Wrong: the quantum section ("training in hours or days") is speculation presented as an expected outcome. The architecture diagram includes a quantum co-processor.
- Wrong: federated learning updates are described as "anonymized". Gradients can leak data; secure aggregation and differential privacy are needed.
- Outdated: the Gemini code uses the old SDK. The edge example uses a fictional SDK (real options: ONNX Runtime, LiteRT, llama.cpp).

### Chapter 30 (Product)
- Mostly timeless. Wrong for the domain: an LLM "agent" predicting time-to-failure from sensor time series. Classical ML is the right core; LLMs explain and summarize.
- Gap: cross-customer data use needs contractual rights; evals belong in the iteration loop.

### README and references
- The chapter summaries are updated to match the corrected content.
- Many references were low-signal (Medium, LinkedIn posts) or irrelevant. References were replaced or augmented with primary sources (papers, official docs, OWASP, OpenTelemetry) where they were changed.

## Out of scope (deliberately not changed)

- Book structure, chapter order and the IoT running example.
- Prose style and voice, except where it made a wrong claim.
- Providing runnable companion code. The book is prose with inline snippets; adding a code repository is a separate project.
- Exhaustive model catalogues and price lists, which go stale within months. The book now points to the providers' live pages instead.
